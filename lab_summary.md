The main challenge was keeping the workflow honest under partial data and unstable network conditions: one earlier context hit a network failure, but the same pipeline later succeeded in the VS Code terminal, which showed that the code path itself was sound. The other issue was that asking for exactly the needed number of articles could leave only one usable item, so the selection logic was corrected to request a small buffer of candidates, keep unique valid articles, and report when fewer than requested were actually available. That reinforced the distinction between discarded records and records not selected because of the limit, and it suggests a future improvement of adding paginated retrieval or source diversification before summarization.
